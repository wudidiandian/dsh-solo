# App ↔ 插件端到端加密

状态：`0.1.5` 已实现并完成功能及实机验证；`0.1.4` 不包含端到端加密。正式安装包见 Releases，服务端由维护者单独部署；升级顺序及回滚见 [升级说明](../deploy/E2EE_UPGRADE.md)。协议尚未经过独立安全审计。

## 安全边界

- 独立的 256 位随机配对凭据通过电脑配对二维码或完整 `dshpair1.…` 配对码交给 App，**不发送给中转**。连接令牌只负责房间路由，不作为加密密钥。
- 每次连接生成临时 X25519 密钥对，双方用配对凭据的 HMAC-SHA256 验证握手。HKDF-SHA256 从共享秘密派生方向独立的 AES-256-GCM 密钥。手机须收到加密的密钥确认后才进入连接成功状态。
- 每个手机、每次重连都有独立连接 ID 和密钥。GCM 认证完整业务信封；AAD 绑定协议域、连接 ID、方向和计数器。96 位 nonce 的后 32 位为单调递增计数，达到上限必须重连。接收端拒绝篡改、重复和乱序帧。
- 会话、项目名、工具参数与结果、任务、审批、附件名和内容均在密文内。外层只包含加密协议类型、随机连接 ID、计数器和密文。中转没有配对凭据、临时私钥和业务解密密钥。
- 新模式不在中转构建会话快照或事件缓存，也不解析 RPC、文件名、文件块。断线历史由电脑端原有历史存储重新加密发送。离线推送正文不再经过中转；推送适配需另行设计。
- 中转仍可见 IP、连接令牌、角色、时间、连接数量、密文长度和流量，并可拒绝或丢弃连接。监控和限流保留；文件大小上限由插件检查，密文在服务器统一按字节限流，服务器无法区分其中的附件和普通命令。
- App 配对凭据使用 `flutter_secure_storage`，旧 JSON 配置迁移成功后删除其中的凭据；安全存储不可用时不回退到明文存储。Android 禁用系统备份。插件密钥文件位于私有状态目录，POSIX 权限为 `0600`；Windows 依赖运行账户的文件 ACL。
- 同一电脑的配对凭据授予完整远程控制权限，已配对手机均视为可信操作者。目前重置会撤销全部手机，尚未提供单手机撤销管理。

端到端加密保护手机与插件之间的通信，不保护已被控制的手机或电脑，也不阻止电脑及其模型服务处理明文任务。本机会话缓存和电脑历史尚未增加应用层静态加密。首次扫码必须通过可信的电脑配对页面；请勿公开新二维码或完整配对码。

本实现使用 Node.js 标准加密 API 和 Dart `cryptography`，协议尚未经过独立安全审计，不能将测试通过等同于已经获得审计认证。

## 协议互通说明

外层继续使用 JSON envelope `v=1`，通过 `hello.*` 中 `e2ee: 1` 协商加密传输。手机额外提供本次随机 `secureId`。中转明确回显 `hello.ok.payload.e2ee=1`；新客户端遇到不支持的中转会拒绝连接。

握手转发为 `e2ee.hello` / `e2ee.welcome`，业务为 `e2ee.data`；`peerId` 由中转绑定到手机连接。握手 transcript 为 UTF-8 JSON 数组 `["dsh-solo/e2ee/1", routingToken, secureId, mobilePublicKey, agentPublicKey?]`。公钥和证明为无 padding 的 Base64URL。手机 HMAC 前缀为 `mobile:`，电脑为 `agent:`。HKDF 输出 64 字节，前半为手机→电脑，后半为电脑→手机。密文采用标准 Base64，末尾拼接 16 字节 GCM tag；AAD 为 `["dsh-solo/e2ee/1", secureId, direction, counter]`。

`e2ee.ready` 在加密信封内完成双向密钥确认。重连丢弃旧通道，不能把旧密文复用到新通道。加密 RPC 的回复仅发回对应手机；跨设备文件传输 ID 在插件内隔离。同步历史通过加密 `session.history` RPC 完成，不依赖服务器对明文消息排序或读取。

新中转默认拒绝未加密客户端。`--allow-legacy` 只供显式迁移或旧协议测试，开启后旧客户端流量仍是原来的非 E2EE 协议；不要在正常加密部署中开启。代码中的 `allowUnencryptedForTests` 也只供旧测试夹具，新 App 和插件产品入口不会设置它。

## 自动化验证

```powershell
npm run build
npm test
npm run test:go
npm run test:release
cd app
flutter test
```

测试包含 Node/Dart 密钥交换与加密互通、错误凭据、篡改和重放拒绝、真实 Go 中转下的快照与 RPC、6 MiB 附件上传、重连、多手机和重置后重新配对。透明代理会采集实际网络信封并检查业务哨兵文本、文件名与加密凭据不在中转流量中出现。

## 本地手机实测

为了避免影响线上服务器，准备的测试套件使用独立局域网中转。套件和机器相关配置均在 Git 忽略的 `.generated/e2ee-local-test/` 下；按该目录的 `README.md` 操作。测试 App 名称为 **DSH-SOLO E2EE**，包名后缀 `.e2ee`，可与正式 App 并排安装；这是 debug 测试构建，不作为正式签名发布包。

测试要求：电脑、手机处于相互可达的同一局域网；允许测试中转端口通过电脑防火墙。无需修改生产 Caddy、Cloudflare 或线上服务。局域网测试可用 WS 验证密文链路，公开部署仍必须使用 WSS，防止连接令牌和传输元数据在网络上暴露。

安装新版插件后建议重置配对，扫描**本次运行的新版插件二维码**。不要使用仓库演示截图里的旧二维码。验收：连接后出现锁图标；项目、任务、附件与模型操作正常；重置后旧手机断开；旧码和错误配对码不能进入已连接状态。

## 正式升级

先部署支持加密的新中转，再升级 App 和插件并重新配对。新中转默认拒绝旧客户端；需要短期迁移兼容时可显式开启 `--allow-legacy`，旧连接仍不具有端到端加密。完成迁移后移除此参数。发布工作流不会自动部署服务器。
