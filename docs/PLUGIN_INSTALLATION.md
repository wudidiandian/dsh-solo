# 桌面版插件安装与市场分发

## 两种入口

- **插件 → 添加插件**：按 npm 包名、Git 地址或本地包目录安装。npm 发布并可访问后，用户可输入 `dsh-solo-agent`。
- **第三方插件市场 dsh-market**：浏览其收录目录。市场使用 `awesome-dsh-plugin/awesome-dsh-plugin` 的目录，npm 发布和目录收录是两个步骤。

申请收录应在维护者准备公开后进行，通过市场右上角的“申请收录插件”查看当前提交要求。此任务只准备包和验证安装，不发布 npm、不公开仓库，也不向第三方提交收录申请。

来源：[市场作者说明](https://github.com/dsh-market/dsh-market#submit-your-plugin)、[官方插件管理器](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/boot/plugin-manager/README.md)。

## 包结构

`packages/agent/package.json` 的 `dsh.bundle.patch` 指向 `cordis.patch.yml`；补丁插入 `dsh-solo-agent` 行，模块入口为内联运行时依赖的 ESM 文件。发布包同时包含图标、中英文元信息、类型声明、README 和许可证。

## 本地构建

在根目录运行：

```sh
npm ci
npm run pack:plugin
```

`prepack` 自动生成单文件入口，随后在临时目录检查包内资源和运行时能否独立加载，打包无需发布 npm。配置规则见 [发布说明](RELEASING.md)。可用 `npm pack --dry-run --workspace=dsh-solo-agent` 检查包内容。

解压 `.generated/dsh-solo-agent-0.1.1.tgz`，在桌面版“添加插件”中输入解压得到的 `package` 文件夹绝对路径。使用独立解压目录可检查安装包是否依赖开发仓库中的文件。

安装后的启用状态、是否需要重启、配对服务及实际连接应分别验证，不能仅凭“安装成功”判断所有功能正常。目录与令牌配置见 [插件说明](../packages/agent/README.md)。

启用后，从侧边栏 **手机配对** 打开配对页，点击 **打开二维码配对页面**。页面自动检测 8790–8799 的本机配对服务；浏览器中可扫码，或点击“查看”显示令牌。更新增加了客户端界面的旧安装时，需要完全退出桌面版再打开；仅关闭窗口可能隐藏到托盘。

## 分发前

1. 完成桌面端安装验证，确认宿主兼容范围。
2. 配置 Android 签名，生成对应 App 和插件安装包。
3. 准备公开后发布 npm，核对包名及版本可从 npm 获取。
4. 再申请第三方市场收录；收录成功后验证搜索和安装。

仓库中的 `marketplace/marketplace.json` 是符合官方 format-1 格式的自建索引模板，不会自动上传到第三方市场。正式托管前应更新发布时间，确保其中版本已发布。

## 0.1.1 连接与列表刷新修复

此修复只更新电脑端插件，沿用现有 App 和中转服务协议，不要求重新安装 APK 或升级服务器。

- 改用 Cordis effect 清理旧插件的连接、配对服务及后台任务，避免停用后的上下文继续收到手机指令。
- 会话读取失败时不发布假空列表；成功读取到真正的空列表时仍同步删除结果，并丢弃晚到的旧快照。
- 心跳改为发送 ping 后等待 pong，避免空闲连接每 30 秒被误判为断线。

本机更新：在“插件 → 添加插件”中选择新包解压后的目录；如果宿主提示同名插件已存在，先卸载旧插件，再添加新目录。保留原来的设备令牌和状态目录。安装后从应用菜单或系统托盘**完全退出 DeepSeek Harness，再启动**，清理旧版遗留的连接；仅关闭窗口可能仍在后台运行。核对版本为 `0.1.1` 后，在手机重新连接并检查连续发送、列表刷新及空闲后发送。

自动化验证包含停用清理、启动过程取消、会话读取失败、快照乱序、空闲心跳及断线恢复；这些检查不能代替用户手机上的最终复测。


## App 0.1.1 连接确认修复

App 会在转发服务器握手后向电脑插件发送只读确认请求，验证成功才显示绿色“已连接”及会话列表。服务器握手、历史缓存和快照都不能单独证明电脑在线。错误令牌或电脑离线时保留设备连接首页，并提示核对令牌和启用插件；两种情况无法仅凭转发服务器握手区分。

更换服务器或设备令牌会清除上一设备的会话、模型、事件、待审批和待发送附件，并忽略旧连接迟到的回调。连接建立后每 10 秒复核电脑状态，单次等待最多 5 秒；收到 `agent offline` 时立即撤销在线状态。电脑离线可能需一个检查周期才会在界面体现。

这项修复需要更新手机 App，兼容现有服务器和 `0.1.0` / `0.1.1` 插件中的确认接口。建议同时使用修复插件生命周期的 `0.1.1` 版本。自动化覆盖错误令牌切换、旧连接回调、离线缓存、恢复配对和连接首页显示；还需手机真机复测。


## 0.1.2 项目选择

升级 App 与桌面插件至 `0.1.2`。项目选择使用桌面版 `workspaceRegistry` 服务，兼容范围调整为 `>=0.2.1-rc.5 <0.3.0`。入口为会话页 **＋ → 选择项目**：仅请求现有工作区的名称和标识，并过滤目录已不存在的项目，不拉取文件树。选择时不会立刻创建空会话；发送首条消息后才创建会话并关联工作区。已有会话中选择项目会转为新会话草稿，原记录保留。再次发送会继续新会话。

插件在创建时重新验证项目，已删除或不可用的项目会拒绝创建，不能由手机传入任意目录替代项目。无需升级中转服务器。项目名称、标识和会话消息仍经过中转服务，这不属于端到端加密。


## 0.1.3 手机新会话缺少工具

修复插件直接调用 `agents.create` 时未传入桌面 Agent 预设初始化的问题。插件读取宿主当前默认预设，在创建参数中记录 `meta.agentPreset`，并通过创建事务的 `setup` 在 Agent 发布前挂载该预设。未成功加载时创建失败，不发布缺少工具的 Agent。工具集合跟随桌面默认预设，不硬编码终端或文件工具列表。

本次只更新插件；继续使用 App `0.1.2`，服务器无需升级。安装后完全退出并重启桌面版，再在手机端新建项目会话验证。旧版本创建且已经对话的手机会话不会自动改变预设，需另建会话。默认预设本身若未包含某个工具，该工具仍不可用。

验证包括默认预设解析、会话发布前挂载、首条消息前工具就绪、预设加载失败时中止创建，以及既有项目关联和连接测试。手机真机上的实际工具调用还需更新后复测。
