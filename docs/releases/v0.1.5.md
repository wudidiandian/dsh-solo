## 端到端加密与移动端体验

- 手机 App ↔ 电脑插件业务通信加入端到端加密：独立扫码配对凭据、经认证的临时 X25519 密钥交换、AES-256-GCM、防篡改和防重放；每台手机及每次重连使用独立会话密钥。
- 会话、工具结果、项目列表、审批和附件在端侧加解密，中转不持有业务解密密钥。IP、连接令牌、时间及流量大小仍可见；公网仍使用 WSS。
- App 配对凭据迁移到系统安全存储；旧明文配置在迁移成功后删除。本地聊天缓存尚无应用层静态加密，协议未经过独立安全审计。
- 工具执行步骤默认折叠；电脑发起的会话同步运行状态；阅读历史时保留滚动位置，提供“回到最新”；修复步骤折叠与滚动状态冲突造成的红色异常。
- 合并高频回复片段，修复重连后最终消息补齐；中转默认消息帧限流调整为 8,000/s、突发 16,000。手机上行字节限流仍默认 1 MiB/s、突发 4 MiB。

## 升级顺序（重要）

1. **自建用户先升级中转**，再升级插件与 App。官方服务由维护者单独部署；npm 发布和 GitHub Actions 不会自动替换服务器进程。
2. 插件安装 `dsh-solo-agent@0.1.5`，完全退出并重启 DeepSeek Harness；手机安装正式签名的 `dsh-solo.apk`。
3. 使用新版插件实时显示的二维码或完整加密配对码重新配对；旧二维码、单独连接令牌不能用于新加密客户端。旧版 App/插件无法连接默认拒绝明文的新中转。

维护者需要先让新旧客户端短期并行时，可显式使用 `--allow-legacy`；旧连接仍不具备端到端加密，完成迁移后移除此参数。新 App/插件不会自动降级到明文。

Linux 服务端文件：Intel/AMD x86_64 使用 `relay-linux-amd64`，ARM64 使用 `relay-linux-arm64`。部署及回滚见 [升级说明](https://github.com/wudidiandian/dsh-solo/blob/main/deploy/E2EE_UPGRADE.md)。

测试版 `DSH-SOLO E2EE` 使用独立 Android 包名；正式版使用原有 `DSH-SOLO` 包名，可与测试版共存，配对信息需要在正式 App 中重新录入。

## English

Adds authenticated phone-to-plugin E2EE for conversations, tools, project metadata, approvals and attachments; platform secure storage for pairing credentials; independent sessions per phone/reconnection; replay protection; and fixes for streaming recovery, collapsed tool steps, desktop running status and history scrolling.

**Upgrade the relay first, then both clients, and scan the new pairing QR.** Legacy QR codes/tokens alone cannot establish encryption. The relay rejects plaintext clients by default; an explicit temporary `--allow-legacy` migration mode does not encrypt old connections. New clients never silently downgrade. Traffic metadata remains visible, endpoint/model services still process plaintext, local history is not encrypted at rest, and no independent protocol security audit has been completed.
